# 2026-10-03 — Fundação do projeto + MVP jogável

**Quem trabalhou:** fundador (sessão solo, com assistente de IA para planejar)
**Duração aproximada:** 4 h
**Ferramenta de IA usada:** assistente de planejamento (DeepSeek) para desenhar o processo;
Claude Code fica para a implementação com o parceiro.

## Objetivo da sessão

1. Definir **como dois devs trabalham juntos**, cada um na sua casa, de forma assíncrona.
2. Recomeçar o código do jogo **já sob controle de versão**, para servir de base e de
   teste do fluxo de subida ao GitHub.

## O que foi feito

- Definimos o processo: **GitHub Flow** com branches curtas, `main` protegida,
  **Conventional Commits**, PR sempre (ver `CONTRIBUTING.md`).
- Estrutura de documentação criada: `README`, `CONTRIBUTING`, `CLAUDE.md`, `STATUS`,
  `ROADMAP`, `CHANGELOG`, `docs/` (arquitetura, categorias, guias, ADRs) e `devlog/`.
- MVP implementado do zero:
  - Backend Node + Express + Socket.IO com salas por código (estado em memória).
  - Lobby (criar/entrar, nome, avatar, host inicia).
  - Rodada com timer, respostas ocultas, revelação, pontuação `= rank` e placar.
  - Resultado final com ranking.
  - Categoria IMDb (snapshot de 100 filmes) populada.
  - Avaliação de categoria (👍/👎) persistida em `runtime/ratings.json`.
  - "Concede" automático quando alguém faz 95+.
  - **Modo offline** (passa-o-aparelho) reaproveitando as mesmas regras do servidor.

## Decisões tomadas

- **ADR-0001** Stack: Node + Express + Socket.IO, servidor autoritativo, frontend sem build.
- **ADR-0002** Escopo do MVP (o que entra e o que fica de fora).
- **ADR-0003** Categorias são snapshots estáticos (sem scraping).
- **ADR-0004** Modo offline reaproveita `src/game.js` via `/shared/`.
